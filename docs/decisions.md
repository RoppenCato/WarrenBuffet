| D10 | 2026-10-11 | Aggregate definition: unit price = buyout ÷ count (rounded, min 1 copper); percentiles quantity-weighted with integer comparisons; bid-only rows count in qty/auctions but not in prices | Python must reproduce the addon's numbers exactly (`pipeline.savedvars.aggregate`) | T7, if AHledger's median is defined differently |
| D11 | 2026-10-11 | Ledger rows are strings `ts,char,event,key=value,…,name=…`; mail is deduplicated on event + item name + count + bid + expiry time | Fields differ per event and may change during beta; the inbox has no mail id | After T6 |
| D12 | 2026-10-11 | Addon stores realm, faction, region and zone per scan; the pipeline maps them to a house id | No API for the ruleset confirmed in Forever. T3: `GetCurrentRegion()` returned 110 on the beta, so region can't be trusted either — map from realm name | At launch |
| D13 | 2026-10-11 | `hasAllInfo` misses are counted, not waited for. A scan is dropped if the AH closes before it finishes | itemID, count, minBid and buyout are valid immediately (wiki); a partial scan would look like mass sell-through. T3 confirmed: 9.7 % misses, all with item, count and buyout | — |
| D15 | 2026-10-11 | Raw rows get a 6th field: the time-left band (1–4) | T3: `GetReplicateItemTimeLeft` works. A listing that vanishes from band 1 probably expired rather than sold — better sell-through estimates. Costs ~0.2 MB per scan | When the band thresholds for 2/8/24 h listings are known |
| D16 | 2026-10-11 | No per-item `SendSearchQuery` scanning | T5: the AH is retail-style, but stackables are in the replicate results | If a later build drops them |
| D17 | 2026-10-11 | Ledger takes cancels and commodity purchases from the player's own clicks (`hooksecurefunc` on `CancelAuction`, `ConfirmCommoditiesPurchase`), and anchors each mail's `daysLeft` to the time it was first seen | T6: `AUCTION_CANCELED` has no auction id, `COMMODITY_PURCHASED` never fired, and `daysLeft` is a snapshot that made one mail log twice. Observing clicks is not automation (D5 stands) | After the T6 re-run |
| D18 | 2026-10-11 | Ledger logs a `money` row for every balance change while the AH or mailbox is open; `dep` on a post row is only the API's estimate. `AUCTION_CANCELED` is not logged | Beta run 2: 1s charged per post where the estimate said 0–8c; the event fired 28 times per scan with foreign ids. Real P&L needs real cash flow | After a run with v0.3 |
| D19 | 2026-10-11 | First dashboard (`dashboard/build.py`) reads the SavedVariables file and the newest pricetable in `data/` directly; no Parquet/DuckDB yet | Asked to show what the data is for before the storage layer exists. Signals live in `pipeline/analytics.py` so they carry over | When the L1 Parquet store exists |
| D20 | 2026-10-11 | Flip candidates are priced against min(today's listing median, AHledger 7-day median), 30 % discount, 50+ sold a day, lot ≤ half a day of sales | A listing median alone overstates the resale price: with it the list filled up with items whose asks had just been pushed up | Tune on launch data |
| D21 | 2026-10-11 | Addon gets an Inventory module: latest bags, bank and own auctions per character, read-only | Sell and repost suggestions need to know what is held and listed; the design had no source for that. Must be tested before the beta ends | After T9 |
| D22 | 2026-10-11 | Dashboard is two pages: **Today** (suggestions with reasons, no charts) and **Market** (all tables and charts). Today is the landing page | The plan is what gets used daily; the detail is for checking it. Today stays small (9 KB vs 5 MB) | When the in-game PlanView exists |
| D23 | 2026-10-11 | Planner v0 rules: sell at ≥ 1.3× the 7-day median or under 0.5 days of stock; hold at ≤ 0.8× (never in launch week); don't post lots under 20s; repost if undercut by more than 5 %; buy per D20. "Normal" price and sell rate come from AHledger until own history exists | First guesses from the playbook so the page has something to show; every suggestion states its reason so a bad rule is visible | Tune against the ledger after two weeks of launch data |
| D24 | 2026-10-11 | News: pull Wowhead's Forever RSS feed, flag by item names and economy terms, and have Claude review the flagged stories on request (prompt shown on the Today page). Outcomes in `plan/news-log.yaml`, lasting ones in the calendar and watchlist | Fetching and flagging can run unattended; judging what a story does to prices needs a reader. Keyword flags alone were too noisy ("ore" matched "Forever") and too shallow | If the queue is ignored for days, or a scheduled review proves reliable |
| D25 | 2026-10-11 | Optional local server (`dashboard/serve.py`, 127.0.0.1 only) with one Refresh button: pull news and prices, re-read the last scan, rebuild | A static page cannot call Wowhead or AHledger itself (browsers block cross-site requests). Pages stay static files and still open without the server | With D7 (hosting) |
